# Master configuration — the code-and-name masters

Six screens behave identically: **Grade Master, Department Setup, New Bank /
NBFC Setup, New Product Setup, New Entity Setup, New Agency Setup.** Each holds
a list with Active and Inactive tabs and a create form of code, name,
description and status.

The cases below are written once and run against every one of them, so each ID
covers six screens. Where a screen differs — a product needs a department, an
entity also asks for a GST number — the difference is noted in the row.

| ID | Case | Steps | Expected |
|----|------|-------|----------|
| MAS-CN-001 | The list opens | Open the screen. | The list renders under its own title, with an Active tab, an Inactive tab, and the button that opens the create form. |
| MAS-CN-002 | Required fields are marked | Open the create form. | Every field the server insists on is marked with an asterisk. A field the server requires and the form does not mark is a defect — it produces a rejection the user cannot act on. |
| MAS-CN-003 | An empty save is refused | Open the create form. Save without typing anything. | The form stays open, and a message appears beside each field that is missing. Nothing is created. |
| MAS-CN-004 | A duplicate code is refused | Create a record with a new code. Open the form again and use the same code. | The second save is refused and the reason appears on screen, next to the code. The first record is unaffected. |
| MAS-CN-005 | A valid record is created | Fill code, name and description (and the department or GST number where the screen asks for one). Save. | The form closes and the new row is readable in the list, showing the code and name that were typed. |
| MAS-CN-006 | Cancelling discards the draft | Open the form, fill it in, press Cancel. | The form closes and nothing is added to the list. |
| MAS-CN-007 | A new record is Active | Create a record leaving Status at its default. | The row appears under the Active tab and not under Inactive. |
| MAS-CN-008 | A record can be deactivated | Open a record's actions and set it inactive. | The row leaves the Active tab and appears under Inactive. | *Driven on the row action menu, on Department Setup — the simplest code-and-name master, so the case is about the ACTION rather than the screen.* |
| MAS-CN-009 | An existing record can be edited | Open a record, change its name, save. | The list shows the new name. The code is unchanged and cannot be edited. | *Same menu, same screen. The new name is read back from the list, where a user would look for it.* |
| MAS-CN-010 | The code is fixed after creation | Open an existing record for editing. | The code field is present but not editable — codes are referenced elsewhere and changing one would break those references. | *Asserted on the field itself: the editor renders Code disabled and says why. The server refusing a changed code is the guarantee; the disabled field is what stops anybody trying.* |
| MAS-CN-011 | Long values are held to the field limit | Type past the limit in code, name and description. | The field stops accepting characters at its limit rather than accepting them and failing on save. |
| MAS-CN-012 | Codes are restricted to safe characters | Enter a code containing a space or a slash. | The form refuses it and says which characters are allowed. | *Not on New Bank / NBFC Setup: a lender's code is entered as the lender writes it, so that screen takes any character.* |
| MAS-CN-013 | A product still assigned to somebody cannot be deactivated | Assign a product to a user, then deactivate that product. | Refused, saying it is still assigned and what to do first. A master that goes inactive under the people holding it leaves them with a set it no longer offers. | *Driven on Product Setup — the department beside it has refused this since MAS-CN-008's cousin, and the two must answer alike.* |
| MAS-CN-014 | A department with active products cannot be deactivated | Create a product under a department, then deactivate that department. | Refused, and the message names the products as the reason. A department that goes inactive while its products stay on offer describes the record and nothing about the workspace. |
| MAS-CN-015 | A product an agent sources cannot be deactivated | Onboard an agent whose service offerings include a product, then deactivate that product. | Refused, and the message says agents are sourcing it. Those agents' payouts cite the product, so retiring it under them changes what a calculation may read while their agreements stay live. |
| MAS-CN-016 | A department with nothing under it still deactivates | Deactivate a department with no agencies, no products and no users. | Accepted, and the row moves to Inactive. A guard that refuses everything is not a guard.
| MAS-CN-017 | A product belongs to several departments, and All picks every one | On Add Product, choose two departments, save, and reopen the product. Then tick All. | Both departments are still chosen on reopening. All selects every department that exists and says how many; it is a snapshot rather than a wildcard, so a department created next week is not covered. A product is sold by more than one department, and choosing the second must not replace the first. |
| MAS-CN-018 | A department cannot be retired while a product merely belongs to it | Give a product a second department, then deactivate that second department. | Refused, naming the products that still belong to it. Belonging counts whether or not the department is the product's primary one — a guard that read only the primary let a department be retired under products that stayed on offer beneath it. |
| MAS-CN-019 | Product Category is mandatory on a product and is shown in the listing | Open Add Product and read the field after the product name. Save without choosing one. | Product Category is there, carrying the mandatory mark, and the save is refused without it. The listing carries a Product Category column after Product Name. | *Driven on Product Setup.* |
| MAS-CN-021 | A product saved before categories existed must be given one before it saves again | Open a product that has no Product Category and save it without choosing one. Then choose one and save. | The first save is refused and the message sits under Product Category; nothing about the product changes. The second is accepted and the listing shows the category against it. The field opens empty rather than guessing, but mandatory applies to every product, not only new ones — otherwise the column stays blank on every product that predates it. This holds for an inactive product too: it can be given any active category. | *Driven on Product Setup.* |
| MAS-CN-022 | Bank / NBFC description is optional | Open Add Bank / NBFC. Fill only code and name, leave the description empty, and save. | Description carries no mandatory mark, and the bank is created. The listing shows a dash for its description. Code, name and status are still mandatory. | *Driven on New Bank / NBFC Setup — the other five screens are unchanged by this.* |
| MAS-CN-023 | A product saved before departments existed must be given one before it saves again | Open a product that has no department and save it without choosing one. Then choose one and save. | The first save is refused and the message sits under Department; nothing about the product changes. The second is accepted and the listing shows the department against it. A product comes under a department, and that applies to every product, not only new ones. An inactive product whose department has since been retired still saves while it keeps that department — only adding a retired department is refused. | *Driven on Product Setup.* |
| MAS-CN-024 | Entity GST number and description are optional | Open Add Entity. Fill only code and name, leave the GST number and the description empty, and save. Then open Add Entity again and type a GST number that is not a valid GSTIN. | Neither GST number nor description carries a mandatory mark, and the entity is created; the listing shows a dash for its GST number and for its description. A GST number that is typed is still checked: the invalid one is refused and the form stays open. Code, name and status are still mandatory. | *Driven on New Entity Setup — the other five screens are unchanged by this.* |
| MAS-CN-025 | A Bank / NBFC code may carry any character | Open Add Bank / NBFC and save one whose code has a space, a dot, an ampersand and a slash in it. Then open the form again and save a code of spaces only. | The first is accepted and the listing shows the code exactly as typed. The second is refused beside the code, because a code of nothing is still missing. | *Driven on New Bank / NBFC Setup — the other five screens still refuse those characters.* |
| MAS-CN-026 | Bank / NBFC asks for no PO% with Bank | Open Add Bank / NBFC, then edit an existing bank, then read the listing. | Neither form has a PO% with Bank field, and the listing has no PO% with Bank column. Editing and saving a bank that was given a percentage before the field was removed still succeeds. | *Driven on New Bank / NBFC Setup. It replaces the earlier case that asked for the field, removed with it.* |


## Product Category Setup

A seventh screen of the same shape, added after the six above. It is listed
separately rather than folded into `MAS-CN-`, because those cases are written
once and run against six named screens — widening that header would claim
sixteen passing cases on a screen nothing has been driven against.

| ID | Case | Steps | Expected |
|----|------|-------|----------|
| MAS-PC-001 | Product Category Setup lists its categories | Open Product Category Setup. | Categories are listed with their code, name, description and status, under an Active tab and an Inactive tab, with the button that opens the create form. |
| MAS-PC-002 | A category is created | Fill the category code, the category name and a description, and save. | The form closes and the new category is readable in the list, under Active, showing the code and name that were typed. |
| MAS-PC-003 | A category needs a code, a name and a status | Save with any of those three empty. | Refused, with a message beside each one that is missing. The description is the one part that may be left out. |
| MAS-PC-004 | A duplicate category code is refused | Create a category, then create a second one with the same code. | The second save is refused and the reason appears beside the code. The first category is unaffected. |
| MAS-PC-005 | A role must be granted the screen before anybody sees it | Open Product Category Setup as a user whose role has not been given it. | It is not in their menu and is refused if reached anyway. This is a new master, so no role holds it until somebody grants it, and a workspace where nobody has will find Add Product asking for a category it has no way to create. |
| MAS-PC-006 | A category that active products use cannot be deactivated, and the screen says why | Deactivate a category that an active product is filed under, and confirm. | Refused. The confirmation stays open and says the category is used by active products, how many, and names them, with what to do first. The category stays under Active. Pressing Deactivate and seeing nothing happen is the defect this replaced. |
| MAS-PC-007 | A category nothing uses deactivates | Create a category, file no product under it, deactivate it and confirm. | The confirmation closes, a message says it was deactivated, and the category is under Inactive rather than Active. |
